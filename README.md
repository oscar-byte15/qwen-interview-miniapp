# Interview Lab — Qwen2.5 + React + Spring Boot

Mini-app for the FH Dortmund **Hands-on Task 1: Build a Mini-App Connected to Qwen2.5**.

It implements the slide's minimum viable flow:

**React candidate UI → Spring Boot backend (hidden assessment prompt) → FH Dortmund Qwen2.5 model**.

A candidate enters a role and topics, receives 2–5 adaptive questions, types answers, and gets a final score, strengths, and improvements. The backend stores sessions in memory for this classroom prototype.

## Prerequisites

- Java JDK 17 or newer (`java -version`)
- Maven 3.9+ (`mvn -version`), OR generate a Maven Wrapper using a local Maven install
- Node.js 20.19+ or 22.12+ (`node -v`)
- Network access to the university model server for **real mode**
- A valid university vLLM API key

### Terminal 1 — Backend (Windows PowerShell)

```powershell
cd backend
$env:QWEN_MODE = "real"
$env:QWEN_BASE_URL = "http://172.22.90.112:8000"
$env:QWEN_MODEL = "qwen2.5-coder-32b"
$key = Read-Host "University vLLM API key" -AsSecureString
$env:QWEN_API_KEY = [System.Net.NetworkCredential]::new("", $key).Password
mvn spring-boot:run
```

If you use Git Bash instead:

```bash
cd backend
export QWEN_MODE=real
export QWEN_BASE_URL=http://172.22.90.112:8000
export QWEN_MODEL=qwen2.5-coder-32b
read -r -s -p "University vLLM API key: " QWEN_API_KEY; echo
export QWEN_API_KEY
mvn spring-boot:run
```

The backend runs on `http://localhost:8080`. The actual model call is sent **directly** to `http://172.22.90.112:8000/v1/chat/completions`. You do not need Claude Code to run this application.

> Keep the key out of git, screenshots, frontend files, and committed Spring application settings. The university network may restrict the server even while connected to eduroam; if requests time out, ask your instructor which network or VPN provides access.

### Terminal 2 — Frontend

```bash
cd frontend
npm install
npm run dev
```

Open `http://localhost:5173`. Vite proxies `/api` to Spring Boot on `localhost:8080`.

### Demo mode (offline; no API key required)

If the university server is unreachable, start the backend instead with:

**PowerShell**

```powershell
cd backend
$env:QWEN_MODE = "demo"
mvn spring-boot:run
```

**Git Bash**

```bash
cd backend
export QWEN_MODE=demo
mvn spring-boot:run
```

Questions and evaluations in demo mode are **simulated** and not generated by Qwen. Switch back to `QWEN_MODE=real` to demonstrate genuine university-model connectivity.

## API

| Method | Path | Description |
|---|---|---|
| GET | `/api/health` | Backend status, model and mode (not model reachability) |
| POST | `/api/interviews` | Start interview with `role`, `topics`, `numberOfQuestions` |
| POST | `/api/interviews/{id}/answers` | Submit answer, get next adaptive question or final assessment |
| GET | `/api/interviews/{id}` | Fetch session |
| GET | `/api/interviews` | List in-memory sessions |

Sample start request:

```json
{"role":"Working Student Software Engineer","topics":"Git, Java, REST APIs","numberOfQuestions":3}
```

Example smoke test for demo mode:

```bash
curl http://localhost:8080/api/health
curl -X POST http://localhost:8080/api/interviews -H 'Content-Type: application/json' -d '{"role":"Java Developer","topics":"Git, Java","numberOfQuestions":2}'
```

## MVP limitations and next steps

- No database, login, PDFs, or audio: not required by the 15-minute slide exercise.
- Sessions are stored **in memory** and disappear if Spring Boot restarts.
- Anyone with access to this local development server can read sessions. **Do not deploy publicly without authentication and authorization.**
- For performance, cap output length and input size. Qwen evaluation is an AI estimate, not an objective certification.
- For production: persistence, rate limiting, HTTPS, input privacy/retention, structured output enforcement, retries, and monitoring.
